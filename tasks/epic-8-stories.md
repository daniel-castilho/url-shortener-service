# Epic 8 – Stories (Acceptance)

| # | Story | Acceptance Criteria (grounded) | Real Reference |
|---|-------|------------------------|--------------------------|
| **8.1** | **Release contract** – write how validated code becomes production, and record the decisions Epic 8 makes (and the ones it rejects). | • `docs/release-engineering.md` with the full flow: annotated tag `vX.Y.Z` → `release.yml` gates (never skipped) → GitHub Release (CI-built jar + sha256 + SBOM + notes) → `scripts/deploy.sh <tag>` on the host → post-deploy verification. Equivalent matrix columns: step, who executes it (CI × operator), what fails, what happens (fail-closed). <br>• ADR 0007: blue-green on bare metal — two concrete units, blue (:8080) / green (:8081), with a **jar per colour** (the current template uses a single shared jar, which prevents a per-colour artifact); the nginx template is the single source of truth, `deploy/runtime/nginx.conf` is **rendered** (never committed, never mutated by the tooling); fail-closed cutover: any precondition/step failing → abort to the old colour at 100%, new colour drained and stopped, non-zero exit with the step named; canary 10/30/100, 30s dwell, smoke after each bump; `deploy/runtime/last-deploy.txt` (previous/current/tag/at). Accepted consequence: post-cutover the fleet = 1 active + 1 idle (1× capacity; 2× capacity requires an extra instance outside the deploy plan — written). <br>• ADR 0008: artifact promotion — the jar **built by the gates job** is the promoted one (single build, Release asset, sha256 recorded); `deploy.sh` downloads the exact Release jar (never a local rebuild); the Docker image is a secondary artifact (non-root + Trivy HIGH/CRITICAL + CycloneDX SBOM); immutable tag (fix-forward `vX.Y.Z+1`, never move the tag); GITHUB_TOKEN only. Rejected: SSH-deploy from CI, registry as a mandatory path, `mvn release:perform`. <br>• `git log --oneline -- docs/adr/ docs/release-engineering.md` pasted in the DoD. | ADR pattern (Nygard); `docs/release-runbook.md` §12; dargent `scripts/deploy.sh` (reference pattern, the owner's own repo) |
| **8.2** | **Artifact identity** — the jar and image carry the tag's semver; a tag with a dirty CHANGELOG does not ship. | • pom: `revision` property (`0.0.1-SNAPSHOT` locally) + `flatten-maven-plugin` (`resolveCiFriendliesOnly` mode); the release runs `./mvnw -B clean package -DskipTests -Drevision=<semver>` → `target/url-shortener-service-<semver>.jar`. Evidence: `./mvnw -q help:evaluate -Dexpression=project.version -Drevision=0.14.0` prints `0.14.0` **and** the package jar name; `./mvnw verify` green with the pattern (no gate broken by flatten). <br>• Dockerfile: `ARG VERSION` + `LABEL org.opencontainers.image.version` (does not change the current build; consumed by the release job). <br>• CHANGELOG gate in `release.yml`: fails if the `## [Unreleased]` section of `CHANGELOG.md` at the tag commit is missing or has entries (keep-a-changelog rule: Unreleased is promoted at the tag, never tag with a draft). Gate test pasted (green run + deliberately red run on a throwaway branch). <br>• The artifact name in the Release follows the tag; `deploy.sh <tag>` resolves the jar by semver, not by "last build". | `pom.xml`, `Dockerfile`, `CHANGELOG.md` (keep a changelog already in use) |
| **8.3** | **Blue-green with fail-closed canary** — `deploy.sh` swaps the version in production without downtime and aborts back on any failure. | • Concrete units `deploy/url-shortener-blue.service` (:8080, jar `/opt/url-shortener/blue/url-shortener.jar`) and `deploy/url-shortener-green.service` (:8081, jar `/opt/url-shortener/green/url-shortener.jar`), with the same hardening as the template (`NoNewPrivileges`, `ProtectSystem=strict`, `KillMode=mixed`, SIGTERM, `TimeoutStopSec=30`, `Type=notify`); the `url-shortener@.service` template **remains** for scale-out ≥3 instances (runbook §12) — the deploy plan is blue+green only. <br>• `scripts/deploy.sh <tag>`: downloads the Release jar (sha256 verified against the published asset) → stages and starts/restarts the idle colour with the new jar (graceful) → readiness wait at `:<porta>/actuator/health/readiness` with a **named budget** (`READY_BUDGET_SECONDS=90` — justified in the script: the Dockerfile HEALTHCHECK uses start-period 40s; 90 = margin for prod boot + fail-fast migrator) → render the runtime conf (green weight 10/30/100, blue the complement) → `nginx -t` **before** `nginx -s reload` on each bump → `scripts/smoke.sh` after each bump → 30s dwell → success: writes `last-deploy.txt`, drains and stops the old colour, one-liner. <br>• **Fail-closed:** any precondition or step fails → render the old colour at 100% + reload + drain/stop the new colour + exit ≠ 0 with the offending step named. The `deploy/proxy/nginx.conf` template is never mutated by the script (single human source of truth); `deploy/runtime/` goes to `.gitignore`. <br>• Template upstream normalized to **two active lines** (blue+green, weight 100/100) — today the 8081 line is commented out; the render replaces those two lines. <br>• Testable modes without touching production: `--check <tag>` (prints plan + last deploy, mutates nothing), `--init` (renders runtime conf blue 100 / green down), `--active` (prints the active colour), `--self-test` (render + weight assertions in a temp dir + proof of the fail-closed abort with dead readiness: `READY_BUDGET_SECONDS=1` against a dead port → aborts to the old colour). Self-test output pasted. | `deploy/proxy/nginx.conf` (current upstream), `deploy/url-shortener@.service`, dargent `scripts/deploy.sh` (architecture reference: awk render, `--check`/`--init`/`--active`, `last-deploy.txt`) |
| **8.4** | **Runtime smoke + one-line rollback** — a single probe proves the stack is serving; a single line undoes the deploy. | • `scripts/smoke.sh <base>`: sequential legs, exit ≠ 0 **naming the failed leg**: (1) `GET /actuator/health/liveness` → 200; (2) `GET /actuator/health/readiness` → 200; (3) `GET /actuator/info` → 200; (4) `POST /api/v1/urls` (anonymous, `originalUrl` unique per run) → **200** + body with `id` and `shortUrl` + `X-Request-Id` header; (5) `GET /<id>` (no follow) → **302** + `Location` == `originalUrl`; (6) `HEAD /<id>` → 302 (HEAD mirrors GET — the EP7 fix, `ReadPathIT#headMirrorsGetOnRedirectPath`); (7) `GET /zzzzzzz` (7 valid Base62 chars) → **404**; (8) `POST /api/v1/urls` with `ttlSeconds: 1` → 200 + `id2`; poll `GET /<id2>` until **410** (15s budget — expiry is checked eagerly in the application, the cache never serves expired). <br>• **Two consumers:** deploy.sh (after each bump, against the nginx front) and CI (the `runtime-smoke` job in `release.yml` — mongo+redis compose/services + the tag's jar + `smoke.sh` + `verify-graceful-shutdown.sh` as the last leg: zero connection-refused during the drain). Contracts read from the code (`ShortenResponse{id, shortUrl}`, the `@ApiResponse` 200 status, `RequestCorrelationFilter` echoing `X-Request-Id`) — pasted in the DoD, not invented. <br>• `scripts/rollback.sh`: reads `deploy/runtime/last-deploy.txt` (previous/current/tag/at) → `systemctl start` the previous colour (its jar **was not touched** — the cutover stopped it, it did not delete it) → render (previous 100 / current down) → `nginx -t` + reload → smoke → incident one-liner (`rollback blue→green reverted to blue at <iso> (deploy <TAG> cut over, panicked)`). No rebuild. `--self-test` (synthetic last-deploy → render assertions). <br>• Runbook §2 now documents `rollback.sh` (the manual procedure becomes a named fallback). | `scripts/smoke.sh` (new), `scripts/rollback.sh` (new), `scripts/verify-graceful-shutdown.sh` (EP7), dargent `scripts/smoke.sh`/`rollback.sh` (reference pattern) |
| **8.5** | **Scheduled, manifested, and verified backup** — the backup runs on its own and the restore is a contract that fails. | • `deploy/systemd/url-shortener-backup.service` (`Type=oneshot`, dedicated user, `After=docker.service`) + `.timer` (`OnCalendar=*-*-* 03:30:00` local — **after** the 02:00 UTC retention purge and the 01:10 UTC rollup, rationale in the comment; `Persistent=true` to pick up a missed run — dargent `dargent-backup.timer` pattern). <br>• `scripts/backup-mongodb.sh` gains a **manifest** (`manifest.json` next to the dump): timestamp, db, mongodb version, size, and **per-collection row counts** (`short_urls`, `users`, `custom_domains`, `click_events`, `click_daily`, `schema_migrations`) — read via `mongosh` (the same tools-in-PATH requirement from EP7, with the `docker exec` fallback documented as in the EP7 drill). The existing 30d rotation remains. <br>• `scripts/restore-mongodb.sh --verify <dir>`: restore + re-count the same collections + compare with the manifest + **exit ≠ 0 on any divergence** (table pasted). Contract: *"a backup without a verified restore is hope"* (dargent E14 — same pattern, same owner). <br>• `scripts/ci-restore-drill.sh` (body of the `restore-drill` job in `release.yml`, locally executable): **isolated** compose project (`urlshortener-drill`, 18xxx ports — EP5/6/7 pattern: never touches the dev stack), seed 20 codes via API + 2 post-backup codes, `backup-mongodb.sh` → drop `short_urls` → `restore-mongodb.sh --verify` → asserts: pre-backup seeds = **302**, post-backup seeds = **404** (RPO = last backup, EP7 drill semantics) + **measured RTO** (wall-clock of backup→restore→verify) ≤ `RTO_BUDGET_S=300`; manifests uploaded as artifacts (the record is the deliverable). <br>• Backup alert failover: **out of scope** (no aggregator/agent exists in the current stack) — the pre-release runbook includes `ls -lt /var/backups/url-shortener | head -1` (backup younger than 26h) and the release drill is the strong guarantee; it becomes a TD item, not a silent gap. | `scripts/backup-mongodb.sh`, `scripts/restore-mongodb.sh`, `docker-compose.yaml`, dargent `deploy/systemd/dargent-backup.{service,timer}` + `scripts/ci-restore-drill.sh` (reference pattern) |
| **8.6** | **Release as a gate** — a `v*` tag only becomes a Release if it passes everything; the runbook reflects the new flow. | • `.github/workflows/release.yml` (trigger **only** tag `v*`; `permissions: contents: read` at the top level, `write` only in the `release` job): <br> 1. job `gates` — checkout `fetch-depth: 0`; `./mvnw -B verify -Drevision=<semver>` (unit+IT+JaCoCo+SpotBugs+Spotless+OWASP on verify); bash gates (`check-boundaries`, `check-security`, `check-metrics-frozen`, `check-doc-sync` + self-tests); promtool check/test + amtool check-config (the same pins as the current CI); **CHANGELOG gate** (empty/absent Unreleased → fail); assembles the release jar and does `upload-artifact` (it is **this** jar that `release` promotes — single build). <br> 2. job `k6-gate` (needs: gates) — mongo+redis services (same pattern as `load-test.yml`), app with relaxed rate limits, `k6 run load-tests/mixed.js` (~2m, nominal rps) — **the k6 exit is already the gate** (the `p95 < 200ms`, `http_req_failed < 0.1%` thresholds are already in the scripts); k6 artifact always. <br> 3. job `runtime-smoke` (needs: gates) — downloads the jar from the artifact, starts app + services, `scripts/smoke.sh`, then `scripts/verify-graceful-shutdown.sh` (drain without connection-refused — EP7 back at the release door); logs on failure. <br> 4. job `restore-drill` (needs: gates) — `scripts/ci-restore-drill.sh` (story 8.5); artifact of the manifests + RTO. <br> 5. job `release` (needs: gates, k6-gate, runtime-smoke, restore-drill) — resolves the tag's semver; `docker build` of the image + **non-root gate** (`docker run --entrypoint id` → fails on UID 0) + **Trivy HIGH/CRITICAL** (SHA-pinned action) + **CycloneDX SBOM** of the image; downloads the jar from the `gates` artifact; `sha256sum`; `gh release create` with jar + `SHA256SUMS` + SBOM + notes (tag annotation + `--generate-notes`). GITHUB_TOKEN only. <br>• `docs/release-runbook.md`: §1 rewritten (deploy = `scripts/deploy.sh <tag>` + post-deploy verification: smoke + 10 min burn-rate watch on the SLO dashboard + `schema.migrations.*` check in the logs), §2 = `scripts/rollback.sh` (the manual procedure becomes a fallback), §7 pre-release checklist extended with: annotated tag; empty Unreleased; **migrations since the `last-deploy.txt` tag are expand-only** (review the `V*` diff — the migrator is fail-fast, but a destructive migration breaks the old blue during cutover); backup younger than 26h; green drill on the release (workflow link).
