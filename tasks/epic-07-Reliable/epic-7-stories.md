# Epic 7 – Stories (Acceptance) [grounded]

| # | Story | Acceptance Criteria (grounded) | Real Reference |
|---|-------|------------------------|--------------------------|
| **7.1** | **Failure contract** — write down what the system does when each dependency goes down, and record the decisions the code already makes (and the ones rejected). | • `docs/reliability.md` with a matrix covering at minimum: Mongo down, Redis down, Redis Stream lag/PEL, stalled worker, OTel collector down, nginx proxy down, Mongo disk/volume. Columns: client symptom, data at risk, detection (metric/log/probe), recovery, target RTO/RPO (explicit that mapping RPO = last backup; click RPO = whatever is in the Stream). <br>• ADR 0005: fail-open vs fail-closed per dependency (rate-limit, tracing, L2 cache, Mongo). <br>• ADR 0006: analytics at-least-once (not exactly-once); retry may duplicate an event; `clickCount` is best-effort. <br>• `git log --oneline -- docs/adr/ docs/reliability.md` pasted in the DoD. | ADR pattern (Nygard); `docs/slos.md`; ADR 0004 already exists |
| **7.2** | **Dependency isolation** — surface circuit breaker + timeout + retry budget on the critical path. Do not reinvent Resilience4j. | • Real inventory: which adapters have `@CircuitBreaker`, which have Spring Data / Lettuce / Redisson timeouts, which retry. Table pasted in the DoD. <br>• Minimal acceptable gap this epic: explicit timeout on the redirect's Mongo lookup and the Redis L2 get (values in `application.yaml`, not magic). <br>• IT: Mongo unavailable on `GET /{id}` cache-miss → contracted response (503 **or** 404 + CB open — the current code decides; the story **fixes the contract in the doc** and the test locks it). <br>• IT: Redis down on the redirect with an L1 miss → rate-limit fail-open preserved; lookup goes to Mongo; latency/status pasted. <br>• Under injection (story 7.5): `databaseCb` transitions CLOSED → OPEN → HALF_OPEN (proof via Resilience4j log / `resilience4j.circuitbreaker.*` metric, **not** relying on an authenticated GET on the Actuator because of debt #26). | `MongoUrlRepository`, `RedisUrlCache`, `RedisRateLimiterAdapter`, ADR 0004 |
| **7.3** | **Honest shutdown and health** – the process drains in-flight; readiness reflects the critical dependency; liveness does not kill the process on a Redis blip. | • `scripts/verify-graceful-shutdown.sh` run end to end; output pasted (in-flight 302; health stops responding after drain). <br>• **liveness ≠ readiness** proof: with the app up, take down Mongo **or** Redis (whatever the current health indicator marks DOWN — measure, don't guess) → `GET /actuator/health/readiness` changes; `GET /actuator/health/liveness` stays UP. `curl -s -o /dev/null -w '%{http_code}'` outputs pasted. <br>• If the current health does **not** distinguish: the gap becomes task 7.3 (adjust indicators) + IT. <br>• nginx `max_fails`/`fail_timeout` cited in `docs/reliability.md` as the on-prem take-out-of-rotation mechanism. | `scripts/verify-graceful-shutdown.sh`, Dockerfile HEALTHCHECK, `deploy/proxy/nginx.conf` |
| **7.4** | **Analytics pipeline recovery** – a worker crash and a bad message neither wipe the Stream nor stop consumption forever. | • Document in `docs/reliability.md`: stream name, consumer group, ack, what stays in the PEL. <br>• Test: publish N events, kill the worker mid-batch, bring it back up → N (or ≥N on retry) in `click_events` + `clickCount` consistent with at-least-once (ADR 0006). <br>• Poison test: invalid payload in the stream → discard metric/log + consumer advances (no infinite loop). Reuse `ClickPipelineIT` / `RedisClickEventQueue*`; extend, don't create a new framework. <br>• Fail-open queue on the redirect **already exists** — surface it with a green test pasted, don't reimplement. | `RedisClickEventQueue`, `ClickBatchWorker`, `ClickPipelineIT` |
| **7.5** | **DR + fault injection under load** – the backup is not a dead script; degradation from a missing dependency is a number, not a narrative. | • **Isolated** infra (not the everyday dev compose): Mongo + Redis + 1 app. <br>• Seed ≥20 codes; `scripts/backup-mongodb.sh`; drop the `short_urls` collection (or restore into a parallel DB); `scripts/restore-mongodb.sh`; `GET /{id}` of the seed codes = 302. Outputs pasted. <br>• Load `load-tests/redirect.js` (short duration, nominal rps) + `docker stop` Redis mid-run: paste p95, `http_req_failed`, status distribution (302/429/5xx). Verdict: aligned with the 7.1 matrix? <br>• Same with `docker stop` Mongo (warm vs cold cache — two runs if time permits; cold cache at minimum). <br>• Update the `docs/release-runbook.md` incident section with the 3 playbooks: Redis down, Mongo down, restore. | `scripts/backup-mongodb.sh`, `scripts/restore-mongodb.sh`, `load-tests/redirect.js`, runbook |
