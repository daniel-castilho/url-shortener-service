# Epic 10 – Stories (Aceitação)

| # | Story | Critérios de Aceitação (aterrados) | Referência Real |
|---|-------|------------------------|--------------------------|
| **10.1** | **Papel ADMIN no token + ADR 0011** — o token carrega o papel, o principal expõe a authority, os bodies de auth expõem `role`; tokens legados não quebram. | • **ADR 0011** registrado no mesmo commit (decisões D1–D4 da overview: role por env list, compat legada, ocupação do slot `ROLE_ADMIN` + consequência nos tiers do actuator, semântica de block, sem revogação em v1 + triggers). <br>• `AdminProperties` (novo, `infra/config/properties/`): `app.admin-emails` (lista; env `APP_ADMIN_EMAILS` comma-separated; vazia = nenhum admin; e-mails normalizados trim/lowercase). <br>• `TokenPort.generateToken(email)` → `generateToken(email, role)`: claim `role` **apenas no access token** (refresh inalterado — superfície mínima); `JwtTokenProvider` emite o claim. <br>• `JwtAuthenticationFilter`: claim → `SimpleGrantedAuthority` `ROLE_ADMIN`/`ROLE_USER`; **claim ausente → `ROLE_USER`** (compat legada, testada). <br>• `UserService`: `AuthResult` ganha `role`; login/register/refresh computam role da env list (não do banco); `me(email)` também retorna role. <br>• DTOs aditivos: `AuthResponse` + `UserResponse` ganham `role` (`"USER"\|"ADMIN"`) — OpenAPI atualizado (o resto do body inalterado: dual-write ADR 0010 intacto). <br>• **Testes desta story:** claim presente no token gerado (unit do provider); filtro → authority correta nos 3 casos (admin/legado/ausente); `AuthResult.role` nos 3 fluxos; `/me` com role; **IT de bootstrap**: registrar com e-mail da list → login body `role=ADMIN` + `/me` `role=ADMIN`; registrar fora da list → `USER`. <br>• **Living spec:** novos requisitos no componente Auth (pacote gated `infra/security`): role claim a partir da env list; token legado sem claim → USER; `/me` retorna role — **todos traced** nos testes desta story. `check-living-spec` verde (Auth ≥ 100%). <br>• `./mvnw verify` + gates bash verdes. **Commit 1** do épico. | `TokenPort`/`JwtTokenAdapter`/`JwtTokenProvider`/`JwtAuthenticationFilter` (`infra/security`), `UserService`, `dto/auth/*`, `SecurityConfig` (tiers `hasRole("ADMIN")` existentes — slot reservado), padrão `SecurityProperties.Operator` (env) |
| **10.2** | **Block/unblock + listagem de usuários** — o operador lista usuários, bloqueia e desbloqueia; bloqueado perde login e refresh (403). | • `User` record ganha `boolean blocked` (apos `name` — ordem do record documentada); mapper da entidade Mongo: **ausente → `false`** (expands-only; **sem V-migration** — `V*` são índices/coleções); `UserEntityTest` estendido (mapeamento nos dois sentidos). <br>• `UserRepositoryPort` + impl Mongo: `findPage(cursor, limit)` e `findPageByEmailPrefix(prefix, cursor, limit)` (sort estável `createdAt desc + id`; prefixo **regex-escaped** — `q` contém `$`/`.` sem quebrar) + `setBlocked(id, blocked)`. <br>• **Pacotes novos** (D3): `core/ports/incoming/admin/` (ports `AdminListUsers`, `AdminBlockUser`, `AdminUnblockUser`), impls em `core/service/` (prefixo `Admin`), `AdminController` em `infra/adapter/input/rest/admin/` — fino: extrai identidade do principal (e-mail + role) e delega; exceções de domínio → handler existente. <br>• **`GET /api/v1/admin/users`**: itens `{userId, email, name, role, blocked, createdAt}` — `role` = **verdade viva da env list** (não o claim); `limit`/`cursor` no estilo do list de urls (mesmo default/cap; `nextCursor`/`hasMore` no DTO); `q` opcional = prefixo de e-mail. <br>• **`POST /api/v1/admin/users/{userId}/block`** e **`/unblock`**: idempotentes, body vazio, **204**; 404 usuário inexistente; **self-block → 400** (rejeitado: sem UI logada o admin não desbloquearia a si mesmo — recuperação viraria Mongo+curl). <br>• **Enforce de block:** `UserService.login` e `refreshToken` — validar credencial **primeiro** (inválida → 401 inalterado), depois `blocked` → `ForbiddenException("Account blocked.")` → **403**. Throttle AUTH (antes do use case) não muda: 429 continua consumindo bucket antes do 403. <br>• **Enforce de ADMIN:** todo use case admin verifica role do caller ≠ ADMIN → `ForbiddenException` (403); anônimo → 401 pela chain. <br>• `SecurityConfig`: matcher explícito `.requestMatchers("/api/v1/admin/**").authenticated()` (autodocumentação; não há catch-all permitAll — o default é `anyRequest().authenticated()`; o teste de ordem é guarda futura). <br>• **Testes desta story:** USER em rota admin → **403**; anônimo → **401**; paginação (3 users, limit 2 → 2+`nextCursor`, pág. 2 = 1 e `hasMore=false`); `q` prefixo ("joa" casa "joao@", não casa "xjoa@"); `role` vivo na listagem; `blocked` visível; block idempotente (2× 204); **login de bloqueado → 403** (e credencial inválida de bloqueado → 401, a ordem); **refresh de bloqueado → 403**; unblock restaura login (200); self-block 400; 404 unknown. <br>• `./mvnw verify` + gates + living-spec verdes. **Commit 2.** | `User` (record), `UserEntity`/mapper, `UserRepositoryPort`, `LinkListResponse`/`PageResult`/`Cursor` (padrão de paginação), `GetLinkUseCaseImpl` (padrão do owner guard com `ForbiddenException`), `GlobalExceptionHandler` (403/404 já mapeados), `BasicOperatorAuthFilter` (não tocar) |
| **10.3** | **Inspeção read-only: links por usuário + lookup por code** — o operador abre a carteira de qualquer usuário (incluindo archived) e encontra qualquer short code. | • **`GET /api/v1/admin/users/{userId}/urls`**: mesmo contrato do owner list (`LinkListResponse`: `items` de `ShortUrlResponse` + `nextCursor` + `hasMore`), **incluindo archived** (`deletedAt` visível — o campo já está no `ShortUrlResponse`); 404 usuário inexistente; cursor no estilo do owner list (mesma estabilidade). <br>• **`GET /api/v1/admin/urls?code=`**: resolve o code **globalmente** (qualquer owner) — **o short code É o id do documento** (verificado: `GET /{id}` usa `findById` direto) → reusa o port existente, **sem método novo de repositório**; resposta = `ShortUrlResponse` + `ownerUserId` + `ownerEmail`; `ownerEmail` **nullable** (doc do usuário ausente — documentado no OpenAPI e testado); 404 código desconhecido. <br>• Read-only: nenhum write nesta story; enforce de ADMIN nos dois use cases (D3). <br>• **Testes desta story:** urls por userId — itens corretos + **item archived exibe `deletedAt`** + paginação; 404 user; lookup 200 com `ownerUserId`/`ownerEmail` corretos; lookup 404 código inexistente; lookup com usuário deletado (via `UserRepositoryPort.deleteById` no setup) → `ownerUserId` presente, `ownerEmail` null. <br>• `./mvnw verify` + gates verdes. **Commit 3.** | `LinkQueryPort` (findById / list por user — já existem), `ShortUrlResponse`/`LinkListResponse`, `GetLinkUseCaseImpl` (404 via `UrlNotFoundException`) |
| **10.4** | **Force archive + write path block check** — o operador arquiva link de qualquer owner; conta bloqueada não escreve mais (lê, sim — v1). | • **`DELETE /api/v1/admin/urls/{id}`**: force archive — **mesma semântica `deletedAt` do owner archive** (`ArchiveLinkUseCase`) + **`urlCachePort.evict(id)`** (padrão em `UpdateLinkUseCaseImpl`); idempotente (**204** em link já archived); 404 link inexistente; enforce de ADMIN. Após: `GET /{id}` (redirect público) → 404 e o owner segue vendo o item com `deletedAt` no seu list. <br>• **Write path block check** (D4): `ShortenUrlUseCase` — quando a request carrega sessão (Bearer **ou** cookie) e o usuário é bloqueado → `ForbiddenException` → **403 antes do shorten** (nada é gravado, nada é contado em quota); o lookup só ocorre **quando há sessão** (caminho anônimo comum sem lookup extra); **limite documentado no OpenAPI/ADR:** shorten anônimo segue permitido (block é por conta, não por IP). <br>• **Sem revogação em v1** (D4): token de acesso de bloqueado segue válido para reads até o expiry — aceito e documentado; follow-up de denylist registrado no **corpo do commit** (e no ADR 0011). <br>• **Testes desta story:** force archive → `GET /{id}` 404 + owner list exibe `deletedAt` + **segundo force archive → 204** (idempotente) + 404 link inexistente; bloqueado com token válido (emitido **antes** do block) → `POST /urls` **403** (e a URL não existe depois) + `GET /api/v1/urls` **200** (lê, não escreve); `POST /urls` **anônimo → 200** mesmo para o e-mail bloqueado (limite documentado). <br>• `./mvnw verify` + gates + frozen-metrics verdes (zero metros novos). **Commit 4.** | `ArchiveLinkUseCase` (semântica `deletedAt`), `urlCachePort.evict` (padrão), `ShortenUrlUseCase`/`UrlShortenerService` (sessão opcional já chega do controller), `ForbiddenException` |
| **10.5** | **Contrato e gates finais** — OpenAPI completo, CHANGELOG, matriz do AGENTS.md, gates do épico e prova viva colada no DoD. | • **OpenAPI** (`/v3/api-docs`): os 6 endpoints admin com `@Operation` (summary/description, params `limit`/`cursor`/`q`/`code`, respostas 200/204/400/401/403/404); `role` documentado nos responses de login/register/refresh/`/me`; semântica **403 "Account blocked."** e **self-block 400** escritas; `ownerEmail` nullable no lookup. A `docs/api-contract.md` da SPA é capturada daqui — **sem isso o doc deles nasce stale** (ADR 0010 R1). <br>• **CHANGELOG** `[Unreleased]` → `### Added`: papel `role` (claim + bodies, aditivo); `blocked` + block/unblock; `GET /api/v1/admin/users` (+`q` prefix); `GET /api/v1/admin/users/{userId}/urls` (inclui archived); `GET /api/v1/admin/urls?code=`; `DELETE /api/v1/admin/urls/{id}` (force archive); write path block check (403). <br>• **AGENTS.md**: item do épico na matriz de debt/status (EP10) + follow-up de denylist/revogação listado (não vira dívida fantasma — tem dono e gatilho); `check-doc-sync` verde. <br>• **Gates do épico:** `./mvnw verify` completo (18 testes de contrato, mapeados em `epic-10-testing.md`); gates bash (`check-boundaries`, `check-doc-sync`, `check-metrics-frozen`, `check-living-spec` + `--self-test`); ArchUnit (use cases admin em application layer — o teste já exigido na story 10.2); living-spec: Auth ≥ 100% traced, componente Admin **ainda não-gated** (a story de 100% do Admin vem depois, como qualquer novo componente). <br>• **Prova viva** (rule zero — colada no DoD, segredos redigidos): boot com `APP_ADMIN_EMAILS=<admin@…>`; register do admin → login (body `role=ADMIN`) → `/me` (role ADMIN); register de vítima; **block** da vítima (204) → login da vítima **403** "Account blocked." → **unblock** (204) → login 200; shorten da vítima → **lookup por code** (ownerEmail correto) → **force archive** (204) → `GET /{id}` **404** → owner list da vítima exibe `deletedAt`. Todos os outputs com status + headers relevantes. <br>• `git log --oneline` do épico (5 commits) colada no DoD. **Commit 5.** | `@Operation`/`@ApiResponse` (padrão dos controllers existentes), `CHANGELOG.md` (keep-a-changelog), `AGENTS.md` (matriz), `scripts/check-*.sh` |
