# Epic 7 – Stories (Aceitação) [aterrado]

| # | Story | Critérios de Aceitação (aterrados) | Referência Real |
|---|-------|------------------------|--------------------------|
| **7.1** | **Contrato de falha** – escrever o que o sistema faz quando cada dependência cai, e registrar as decisões que o código já toma (e as rejeitadas). | • `docs/reliability.md` com matriz cobrindo no mínimo: Mongo down, Redis down, Redis Stream lag/PEL, worker parado, OTel collector down, proxy nginx down, disco/volume Mongo. Colunas: sintoma cliente, dado em risco, detecção (métrica/log/probe), recuperação, RTO/RPO **alvo** (explícito que RPO de mapping = último backup; RPO de click = o que estiver no Stream). <br>• ADR 0005: fail-open vs fail-closed por dependência (rate-limit, tracing, cache L2, Mongo). <br>• ADR 0006: analytics at-least-once (não exactly-once); retry pode duplicar evento; `clickCount` é best-effort. <br>• `git log --oneline -- docs/adr/ docs/reliability.md` colado no DoD. | Padrão ADR (Nygard); `docs/slos.md`; ADR 0004 já existe |
| **7.2** | **Isolamento de dependência** – evidenciar circuit breaker + timeout + retry budget no caminho crítico. Não reinventar Resilience4j. | • Inventário real: quais adapters têm `@CircuitBreaker`, quais têm timeout Spring Data / Lettuce / Redisson, quais retry. Tabela colada no DoD. <br>• Gap mínimo aceitável neste épico: timeout explícito no lookup Mongo do redirect e no get Redis L2 (valores no `application.yaml`, não mágicos). <br>• IT: Mongo indisponível no `GET /{id}` cache-miss → resposta contratada (503 **ou** 404 + CB open — o código atual decide; a story **fixa o contrato no doc** e o teste trava). <br>• IT: Redis down no redirect com L1 miss → fail-open de rate-limit preservado; lookup vai ao Mongo; latência/status colados. <br>• Sob injeção (story 7.5): `databaseCb` transita CLOSED → OPEN → HALF_OPEN (prova via log Resilience4j / métrica `resilience4j.circuitbreaker.*`, **não** depender de GET autenticado no Actuator por causa da dívida #26). | `MongoUrlRepository`, `RedisUrlCache`, `RedisRateLimiterAdapter`, ADR 0004 |
| **7.3** | **Shutdown e health honestos** – processo drena in-flight; readiness reflete dependência crítica; liveness não mata o processo num blip de Redis. | • `scripts/verify-graceful-shutdown.sh` executado de ponta a ponta; output colado (in-flight 302; health deixa de responder após dreno). <br>• Prova **liveness ≠ readiness**: com app up, derrubar Mongo **ou** Redis (o que o health indicator atual marca DOWN — medir, não adivinhar) → `GET /actuator/health/readiness` muda; `GET /actuator/health/liveness` permanece UP. Outputs `curl -s -o /dev/null -w '%{http_code}'` colados. <br>• Se o health atual **não** distingue: gap vira task 7.3 (ajustar indicators) + IT. <br>• nginx `max_fails`/`fail_timeout` citados no `docs/reliability.md` como o mecanismo de tira-de-rota on-prem. | `scripts/verify-graceful-shutdown.sh`, Dockerfile HEALTHCHECK, `deploy/proxy/nginx.conf` |
| **7.4** | **Recuperação da pipeline de analytics** – crash do worker e mensagem ruim não apagam o Stream nem param o consumo para sempre. | • Documentar no `docs/reliability.md`: nome do stream, consumer group, ack, o que fica no PEL. <br>• Teste: publicar N eventos, matar o worker no meio do batch, subir de novo → N (ou ≥N se retry) em `click_events` + `clickCount` coerente com at-least-once (ADR 0006). <br>• Teste poison: payload inválido no stream → métrica/log de descarte + consumer avança (não loop infinito). Reusar `ClickPipelineIT` / `RedisClickEventQueue*`; estender, não criar framework novo. <br>• Fila fail-open no redirect **já existe** — evidenciar com teste verde colado, não reimplementar. | `RedisClickEventQueue`, `ClickBatchWorker`, `ClickPipelineIT` |
| **7.5** | **DR + injeção de falha sob carga** – backup não é script morto; degradação sob falta de dependência é número, não narrativa. | • Infra **isolada** (não o compose de dev do dia a dia): Mongo + Redis + 1 app. <br>• Seed ≥20 códigos; `scripts/backup-mongodb.sh`; drop da collection `short_urls` (ou restore em DB paralelo); `scripts/restore-mongodb.sh`; `GET /{id}` dos códigos seed = 302. Outputs colados. <br>• Carga `load-tests/redirect.js` (duração curta, rps nominal) + `docker stop` Redis no meio: colar p95, `http_req_failed`, distribuição de status (302/429/5xx). Veredito: alinhado à matriz 7.1? <br>• Idem com `docker stop` Mongo (cache quente vs frio — dois runs se o tempo permitir; no mínimo cache frio). <br>• Atualizar `docs/release-runbook.md` seção incidente com os 3 playbooks: Redis down, Mongo down, restore. | `scripts/backup-mongodb.sh`, `scripts/restore-mongodb.sh`, `load-tests/redirect.js`, runbook |
